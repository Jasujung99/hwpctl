# 비공개 참조 문서 재현 실험

이 폴더는 난도 높은 한/글 문서를 재현하면서 발견한 브리지 기능 공백을
**재현 가능하게 기록하고, 일반 기능만 `hwpctl`로 승격**하기 위한 실험 하네스다.

## 경계

- 원본 HWP, HWPML, 추출 이미지, 생성 문서와 개인 경로는 Git에 넣지 않는다.
- 로컬 `private/`는 `.gitignore` 처리된 보존 위치다. 재현기·대조기의 원본 스냅샷,
  실행 로그, 해시 manifest만 둔다.
- 제품 코드에는 원본 문서의 문구·표 순서·수치에 의존하는 보정 로직을 넣지 않는다.
- HWPML은 원본 분석을 위한 읽기 전용 입력일 뿐, 문서에 다시 주입하지 않는다.

## 승격 기준

1. 사설 재현기에서 일반적인 한/글 동작으로 확인한다.
2. 공개 Engine/CLI/MCP API로 작게 분리한다.
3. 합성 HWPML 픽스처와 COM 스텁 테스트를 추가한다.
4. 재현기는 직접 COM 호출 대신 새 공개 API를 사용하게 바꾼다.
5. 구조 대조와 같은 렌더러 기반 PPM 대조를 모두 통과해야 시각 재현이라고 판정한다.

현재 첫 대상은 다음 네 가지다: 중첩 표 탈출, 셀별 그리드 크기, 정밀 글자·문단
서식, 읽기 전용 구조 대조.

## 현재 제공하는 안전한 기반

- `hwpctl.reference.capture_hwpml_readonly(...)`는 별도 한/글 인스턴스에서
  `readonly:true`로만 문서를 열고, 원본 SHA-256을 열기 전후로 확인한 뒤 메모리
  HWPML을 돌려준다. 저장·다른 형식으로의 변환·원본 경로를 포함한 보고서는 만들지
  않는다.
- `hwpctl.reference.compare_hwpml(...)`와 `compare_structure(...)`는 순수
  HWPML 구조 비교다. 스타일 ID, A1 열 문자열, mm 반올림에 의존하지 않고, 빈 문단
  삽입 뒤의 표도 의미 지문으로 맞춘다. 보고서에는 원문 문자열과 로컬 경로를 넣지
  않는다.
- 표 테두리는 셀 속성이 아니라 실제 공유 격자 경계로 정규화한다. 따라서 같은 선을
  인접 칸의 반대쪽에 저장한 표현 차이는 허용하고, 실제 충돌은 별도로 보고한다.

이 계층은 아직 CLI/MCP 명령이 아니다. 합성 픽스처로 계약을 고정한 실험 기반이며,
공개 작성 API의 기능 공백을 판별하는 데 쓴다.

HWPML의 `PageBreak` 같은 내부 속성은 비교 대상으로는 남기되, 곧바로
`page_break_before` 작성 명령으로 번역하지 않는다. 난문서에서는 같은 속성이 실제
PDF 쪽 흐름과 일대일 대응하지 않을 수 있으므로, 새 작성 API로 승격하려면 한/글
렌더 회귀 테스트가 먼저 필요하다.

## 시각 검증의 전제

PDF/PPM 대조는 같은 한/글 버전과 같은 Poppler DPI로 두 문서를 각각 읽기 전용
내보낸 뒤 수행한다. 이때 **COM의 즉시 `PageCount` 값은 물리 렌더 쪽수의 근거가
아니다.** 레이아웃 갱신 전의 세션 값일 수 있으므로, PDF 내부 페이지 트리 또는
`pdfinfo`의 쪽수를 기준으로 삼는다.

두 PDF의 물리 쪽수가 다르면 곧바로 시각 불일치로 종료한다. 일부 앞쪽만 억지로
픽셀 점수화하지 않는다. 쪽수가 같을 때만
`hwpctl.hwpx.compare.compare_page_images(...)`로 페이지별 픽셀 차이와 오버레이를
만든다.
